## System build stages

### Verified increment: pause, recovery and restore

Outcome: changing a running job to Pause stops its exact worker process and preserves evidence; loss of queue control blocks further execution. Verified quota failures may hand off once to each explicitly named subscription fallback, retaining checkpoints. A private, checksummed job backup can be restored into a new empty directory without credentials, overwrites or automatic execution.

Contract: A:G remain Dot/owner inputs; H:P remain runner output. Active control is checked between phases and every five seconds while running. Paused/blocked work requires an explicit resume after Ready and verified process exit. Only recognized provider quota errors permit a bounded fallback; authentication, validation, unknown errors and uncertain Google writes do not. A successful-but-disconnected write is reconciled by reading the exact intended values rather than repeating the mutation. Backups contain validated operational JSON only, exclude credentials/configuration/raw logs and require the execution lock; restore refuses running state, corrupt manifests, unsafe paths and existing destinations.

Acceptance: demonstrate active pause/confirmed exit and checkpoint-preserving resume; simulate quota and ambiguous-write boundaries without exhausting accounts; demonstrate backup/restore with unchanged evidence and no new model invocation. Keep simulated provider failures distinct from actual account exhaustion. Verify controlled Google records, meaningful failure tests, private receipts and two review passes before merging. No recurring schedule or outreach is enabled by this increment.

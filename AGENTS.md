# Working instructions

- Read BRIEF.md and TASKS.md before implementation. Keep WORKSPACE.md links current.
- Build the smallest complete customer journey. Do not add dependencies or skills without a concrete task need.
- Show working previews early. Explain decisions and verification in plain language.
- Use focused commits; preserve user changes. Record actual run/build/test commands in README.md once available.
- Verify forms end to end, responsive layout, keyboard access, errors, and reduced motion as relevant. Add meaningful tests for behavior and bugs, not tests that merely mirror implementation.
- Keep secrets in environment configuration; commit only placeholder examples. Never commit prospect lists, client data, local credential files, or generated tool reports containing secrets.
- Label concept projects honestly; never invent results or customer endorsements.
- Keep outreach draft-first. Do not send messages or start paid services without the user's authorization for those actions.
- Update TASKS.md when a deliverable is complete or a material decision changes. Do not install broad overlapping workflow packs by default.

# PDF review and handoff

Read for either concept mode. Use the available PDF skill for authoring, rendering, and inspection; use the task's bundled workspace dependencies where available. Reuse suitable existing review tooling rather than installing a new design stack.

## Compose for a real review

The owner's reference is a concept book with a large website visual beside a concept name, short reasoning, proposed motion, and tradeoffs. Match that useful comparison format while letting this company's material determine the design. In the Ensizziyo workspace, the historical examples are `output/pdf/W1-Ensizziyo-ten-homepage-concepts.pdf` and `output/pdf/W1-Ensizziyo-Cinema-and-Gallery-variations.pdf`; these files are optional references, not required dependencies.

Use a clear cover or opening identifier with the company, review type, and concept status. Give each direction enough space to judge its visual hierarchy. Use additional enlarged or continuation pages when needed for readable design and text; page count serves legibility, not a fixed one-page rule. Avoid tiny contact sheets and unrelated decorative document pages.

Keep the review's explanatory notes distinct from the proposed website or advertisement. Do not put internal source notices, implementation instructions, or review controls inside a company's customer-facing composition unless the design calls for them.

- **Prospect:** concise visual pitch with large designs, brief business relevance, a recommendation, and a clear next discussion. Keep technical or detailed review material in short supporting notes.
- **Paying client:** the same visual standard with fuller reasoning, content and image choices, proposed interaction, tradeoffs, and consequential unresolved decisions.

Include a concise comparison and recommendation. Keep proposed motion explicitly described as a proposal. A campaign PDF should clearly group each idea's post, ad, and matching landing-page sample.

## Keep originals and provenance

Place actual company image files into authored layouts with proportional scaling/cropping, and preserve those originals. Choose a composition method that supports exact assets and readable text. If using image generation to explore ideas, its reference handling alone does not guarantee unchanged logos, products, or photography; final asset placement must meet the original-image requirement.

Record source URLs or supplied filenames, capture dates where useful, and which images are company originals versus supporting stock. Track any assumptions, proposed offers, image gaps, and reuse-rights questions in concise review notes or the authorized private project record. A public source does not by itself establish permission for a later public campaign. Do not turn source bookkeeping into repeated warning banners across the mockups.

Store real company material and reviews in an authorized client folder or task output directory **outside the studio Git repository**, including when a PDF skill has a generic repository output default. Use safe company slugs and descriptive filenames such as `company-website-concepts.pdf` or `company-campaign-concepts.pdf`. A private companion source record can preserve inputs and selections; no prospect list or client assets belong in the reusable skill.

## Inspect the exported result

Render every final PDF page and inspect the renders. Check complete image placement, legible type, clipping, alignment, logo/photo fidelity, and useful reading scale. Fix issues in the authoring source and re-export before delivering.

In a separate requirements pass, verify the requested concept counts and depth, company identity, original image use, accurate copy, chosen presentation audience, and sample material coverage. Check repeated offer details and buttons agree across a campaign's three materials. Confirm that mobile layouts were not silently added to an initial desktop-only website review.

Keep these visual checks separate from claims about working behavior. Static PDF verification does not establish browser accessibility, responsive runtime behavior, motion performance, ad-platform approval, or public publication readiness.

Deliver the PDF with a short recommendation and a selection/refinement prompt. Follow the active PDF skill's file-delivery convention. State any material missing source or unverified assumption, and retain earlier review versions and accepted selections for later refinement.

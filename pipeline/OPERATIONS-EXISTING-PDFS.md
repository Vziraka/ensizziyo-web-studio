# Existing PDFs in the operations desk

Approved November 1, 2026. This bounded increment extends only an explicitly prepared `shared-operations-desk-v1` manual workspace. A new immutable source manifest and namespace must declare `operations_pdf` with schema version 1, mode `registered-existing-pdfs`, at most 64 assets and 16 versions per asset. Existing manifests retain their denials.

Both signed operators may register an existing Drive PDF reference with exact operator-provided source metadata, restore its retained bytes, inspect originals, and explicitly select/dispute a baseline using the established attributed reducer. Resolve an existing company first; any new workspace is private context only, without contact routes or research qualification. Registration and upload never create approval. A changed source requires a new immutable version. The hosted desk does not fetch Drive or establish provider freshness.

The caller accepts closed record/reserve/complete JSON and exact one-megabyte binary chunks. Actor comes from the signed session. Original storage remains bounded to 64,000,000 bytes, attachment selection to two PDFs and 20,000,000 combined bytes. Larger sources remain external references. Baseline review follows visual inspection of the exact verified original. Inspection is available after handoff/stop; reply content/send review remains assigned-operator-only.

Canonical commits exclusively replay typed PDF transitions against the untouched before-state and immutable bytes, compare the entire candidate state/configuration/source binding, and check current authority and the 25-second invocation deadline before CAS. Immutable bytes alone confer no retrieval authority. Lost acknowledgements reconcile only an exact saved envelope. Concurrent changes require refresh; no callback or external effect is automatically replayed.

Partial transfers remain visible and resumable. Complete portable backups retain verified bytes and metadata; unresolved partial-original recovery remains held rather than dropping history or promising a complete cross-namespace restore. Authoring, refinement, audio, Drive OAuth, generic project edits and extra sending paths remain unavailable.

Acceptance requires actual signed owner registration/upload and separate friend manifest/chunk reads; malformed/forged/mixed/stale/old-profile/CSRF requests fail closed; conditional-store race, late write and lost-ack checks; exact reply attachment freshness and limits; complete backup/restore; disabled prepared ZIP imports; desktop and 400px browser inspection. Independent requirements and engineering reviewers must review the frozen implementation. Source tests do not establish live latency, provider freshness, client PDF approval, powered-off operation or real delivery.

Implementation and verification status is recorded in TASKS.md. Existing storage/reply helpers and signed sessions are reused without new dependencies.

## Preparation and signed caller

Pass the explicit `operationsPdf` policy from [the placeholder example](operations-pdf.example.json) to `prepareManualWorkspace` alongside the existing mailbox/work/clock/delivery/discovery policies. The source manifest pins its hash and the three typed transition kinds. Installation still defaults to dry run, requires an empty exact destination for `commit:true`, and keeps every execution/runtime/release flag disabled. Never replace a deployed manifest in place. Removing the opt-in in a separately prepared binding restores the old denial; rollback does not delete retained source/approval/transfer history.

`POST /desk/api/operations-pdf/record` accepts `{revision,event,source}` for `asset_registered`/`asset_version_registered`, `{revision,event,inspected_original:{sha256,bytes}}` for `asset_version_selected`/`asset_version_disputed`, or `{revision,event}` for the private-context-only `workspace_project_created`. Event fields are `id,type,prospect_id,at,data`; the server replaces time and obtains actor from the signed session. Asset events use `studio-assets`; workspace creation uses the new project ID. Exact source fields are `reference,name,mime_type,modified_time,account,sha256,bytes`; reference is `drive:<exact-file-id>`, MIME is `application/pdf`, modified time is ISO UTC, and account is an email or null. Workspace data is only `name,purpose,controlled:false`.

For exact existing project/asset/version IDs, `/desk/api/project-original/:project/:asset/:version` supports GET manifest and GET `/chunk/:index`. POST `/reserve` accepts `{revision,context_sha256,manifest,source}`; its source omits hash/size, which are pinned in the manifest and registered metadata. POST `/chunk/:index` carries at most 1,000,000 binary bytes and the exact `X-Studio-Transfer` header. POST `/complete` accepts `{revision,context_sha256,transfer_id}`. All POSTs require current same-origin session and CSRF token. JSON bodies are bounded to 120,000 bytes. The 25-second request deadline covers opening state, body reads, immutable effects and canonical replay/CAS. GETs do not grant approval or broaden saved-reply-only `/api/project-asset` reads.

The browser uses WebCrypto to hash the selected File and assemble/hash verified chunks into a local PDF Blob. Only successful exact original retrieval exposes the explicit visual-inspection checkbox and baseline/dispute controls. Only one local preview remains open at a time; replacement revokes its prior Blob. Auto-refresh waits during an upload or displayed inspection. A conflict requires fresh state; unavailable/uncertain writes require exact readback before retry. Partial transfers remain listed and accept the same file for resume; no abandon/delete control or cross-namespace partial recovery claim is added.

## Source verification

The final affected run passed 192 tests across 21 suites/files. Focused suites cover signed owner registration/upload, a separate friend session's exact chunk download, approval remaining absent until explicit review, same-project inspection after handoff/stop, old-policy/CSRF/session denial, closed metadata, exclusive whole-state replay, concurrent reservation, unrelated-project CAS race, late writes, missing chunks, identical retry, lost acknowledgement and complete G1 export/restore. Existing reply/task suites exercise scoped/studio permission, two PDFs/20 MB, content/send ownership, saved bundles and baseline/source staleness. `npm run check`, the site/desk builds and actual prepared Netlify ZIP/import verification are part of the release check.

Local synthetic browser proof used a 13,075,423-byte one-page PDF, owner register/upload/inspect/explicit baseline review, separate friend inspection, desktop and a 400px viewport without horizontal overflow. Chromium's native PDF viewer and a separate Poppler raster displayed the fixture. This is a small-state local proof; combined 12 MB state latency, live storage, real client documents, actual teammate identity and powered-off operation remain unverified. Screenshots, fixture and ZIP checks stay in private evidence outside Git. Independent final requirements/engineering review and CI remain parent release gates.

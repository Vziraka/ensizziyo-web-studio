# Disabled shared manual records and internal dispatch

`shared-manual-internal-dispatch-v1` joins the five signed human records from [manual recording](SHARED-MANUAL-RECORDS.md) with the existing [registered incoming and internal dispatcher](SHARED-INTERNAL-DISPATCH.md). It uses the existing `dispatchBinding`, one namespace and `workspace` CAS key. The old internal-only capability remains human-read-only; manual, inert, project, research and refinement capabilities retain their own gates.

The [new example policy](shared-manual-internal-dispatch.example.json) remains UNAPPROVED with actual recipients, grant, deployment, dates and finite allowances blank. No flag, schedule, actual grant, migration or activation is included. A new exact manifest and policy bind `manual_events:{version:1,events:[note_added,call_logged,call_claimed,follow_up_handed_off,contact_stopped]}`. An old dispatch manifest cannot gain these edits through environment flags.

## Signed manual caller

POST `/desk/api/event` accepts exactly those five events from the signed owner or friend, with the current revision and stable event ID. It reuses `applyManualRecord`, including strict completed human call time, `manual_attested:true`, `desk:true`, original simulated/actual identity, chronology, assigned-only continuation/handoff, callback timing, two-call campaign cap and local DNC. The first caller owns follow-ups; agreed callback times take precedence over next-business-day 9am Eastern reminders. Outcomes retain the existing held previews and three-business-day final follow-up timing. Human outcomes do not run automatic project/mockup preparation.

Manual records and either-role DNC remain available while standing dispatch is unapproved, paused, expired or runtime-disabled. New follow-ups and suppression requests stay held; external suppression is unverified. Actual dialing, microphone, sending, provider writes, bookings, research and authoring controls are unavailable. Both roles retain saved history, context, retained-source, original and follow-up reads, plus the existing exact internal controls and complete G1 backup reads. Transfer writes and unrelated provider/OAuth routes are rejected.

The store accepts exactly one typed `manualRecord` or `dispatchTransition`. It independently replays the entire resulting state with immutable configuration and manifest hashes. The CAS callback captures mutation time after storage awaits. A new manual event prepares current attention with `includeDigest:false` in the same CAS, resolving obsolete assignment/source attention without running a sender. Exact event/actor retries reconcile saved fingerprints before stale-revision checks, producing neither another revision nor another preparation. Changed payloads or actors with the same event ID reject. The browser retains the exact pending input across uncertain saves and reload, requires its original actor for retry and offers saved receipt lookup.

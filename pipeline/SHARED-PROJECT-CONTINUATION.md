# Disabled shared project continuation

This source increment connects production-shaped shared records to the existing interactive project workflow. It is separately disabled and requires a new exact binding; `inert-shared-v1` remains notes-only, `shared-manual-records-v1` remains manual records, and the default fictional preview is unchanged. No real import, remote configuration, deployment, provider execution or production release is part of this increment.

## Caller and authority

Local preparation uses `prepareProjectWorkspace({backup, sourceConfig, scope})` with a verified complete G1 package. `scope` has the exact schema/version, `shared-project-continuation-v1` capability, workspace/run/production identity, state schema, HTTPS origin, site/deploy IDs and a new `evz-project-shared-...` namespace. The resulting immutable manifest binds the original state/configuration hashes, every dependency and fresh execution-disabled configuration. Records keep their production mode and original controlled identity. Historic approvals, budgets, attempts, uncertain actions and requests remain evidence; none becomes executable.

`installProjectWorkspace(store, packet)` validates only by default. An explicit local `commit:true` requires the same bound ConditionalLifecycleStore, an empty destination, immutable upload/readback of every original, portable Node authoring and recovery sidecar, retained audio dependency, then complete stored-inventory verification before state publication. It never overwrites or seeds through an HTTP route. Preparation rejects the entire installation before any destination writes/publication when a complete package contains unsupported legacy local runtime/image/font/renderer dependencies, identifying the blocking retained paths. It never filters a mixed-history package into a partial shared backup. Original local G1 backup/restore continues retaining those opaque historical dependencies without executing them; preserve the complete package and use separately reviewed recovery rather than treating local executable paths as portable resources. Installation and future migration require their own authorized setup; no environment values or records were installed remotely here.

The future disabled handler requires all of:

- `EVZ_OPERATIONS_DESK_ENABLED=shared-project-continuation-v1`
- `EVZ_OPERATIONS_PROJECT_BINDING` containing the exact scope and manifest hash
- Exact matching origin, namespace, `SITE_ID` and `DEPLOY_ID`
- `EVZ_OPERATIONS_PROJECT_AUTHORING=shared-project-node-v1` for the authoring caller
- Existing individual owner/friend keys and session configuration, supplied through environment configuration

Do not reuse an inert/manual binding, relax the deployment checks, change records to fictional mode, or copy credentials into a package. Rollback is to leave these flags unset and preserve the immutable source package/namespace; no cleanup or replay is implied.

## Supported human work

Both signed operators can retrieve saved current project context, exact registered original PDFs, editable source, preferences, approved baseline and conflicts. Existing Assets feedback/approval/disagreement controls and Clients & support preparation controls are available. Unsupported creation/output-attestation controls stay hidden. This capability permits only `note_added`, `asset_feedback_added`, `asset_version_selected`, `asset_version_disputed`, `project_preparation_requested`, `concept_refinement_requested` and `unpaid_refinement_exception`. Each event has a strict field allowlist, signed attribution, stable ID, explicit timestamp and exact revision. The store independently replays the existing lifecycle reducer and compares the entire resulting state/configuration/manifest. It cannot accept an arbitrary project subtree write. Automatic notification preparation and monitoring-cycle mutation are excluded from this human-record path.

Feedback keeps the actual words, source version and scope. Supported explicit font/background preferences apply through the existing preference engine; tentative/stale items require author review. Conflicting operators preserve the approved value/composition, and asset disagreements resolve only after both operators select the same version. An included unpaid round or an explicit unused exception is still required. Either operator has equal design authority; the existing project assignment and preparing-job actor remain exact. This source increment adds no assignment or call-placement authority; existing manual ownership/handoff remains a separate capability.

Use `connectSharedAuthoring({origin, key, fetcher?})` in `hosted-authoring-client.mjs`: `begin(name, kind)`, exact `download`, `render(job, source, runtime)`, `rasters`, `complete`, `inspect`, `recovery`, `reconcile`, `revise` and `backup`. This is a source-ready signed interactive Node caller. It runs no model, provider, background semantic executor or arbitrary program. A Ready task, every approved/requested original, exact current context and actor claim are mandatory. Proposals still require the exact retained operator-approved quote and approved template.

Existing authoring mutations now use typed transitions for claim, render reservation, pinned renderer binding, rendered receipt, held attempt, revision and completed publication. At the shared CAS store, immutable originals/source/runtime/export/raster witnesses are independently checked and the exact whole-state transition is replayed. Context/assignment/stop/baseline changes hold publication. Only reviewed output adds a new immutable unapproved asset version and exact held companion draft; it never advances the baseline or creates a send intent. Both signed operators may inspect retained current/historic jobs within this bound workspace; only the preparing actor may mutate that job.

## Recovery, bounds and evidence

Originals/files use existing immutable 1 MB chunks and whole-file hashes. State remains capped at 20 MB; complete backup snapshots above 3 MB use the same backup caller with bounded state chunks, exact snapshot/hash verification and a small manifest. Small packages keep their prior wire format. Dependency files retain existing 64 MB per-file, 512 MB total package, 6,000-file and 16-page limits. Every actual PDF raster is separately retained and bound to the exact PDF; canonical layout JSON cannot stand in for visual review.

An unfinished attempt blocks complete backup until explicit observation/CAS reconciliation. Available, missing, partial and corrupt observations remain inert recovery evidence; closure fences publication and never asserts that an in-flight renderer stopped. Required published dependencies fail closed on missing/corrupt bytes. Complete portable G1 backup/restore keeps originals, editable source, portable font/image/runtime resources, raster review, provenance, historic attempts and held attachments. New execution after restoration requires a fresh deliberately trusted binding; old pending external effects remain subject to provider reconciliation and separate release.

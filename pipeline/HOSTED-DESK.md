# Protected shared-desk preview

This is an execution-disabled fictional proof of the existing desk on Netlify Functions and one strongly consistent conditional-write blob. The existing local runtime is unchanged. Production context always returns 503 for this endpoint; no production records, credentials, Drive files, connectors or workers are copied into it.

The function exposes `/desk/`, its UI assets, authenticated `/desk/api/state`, operator login/logout, lifecycle events and draft/history previews. The same event validation, operator attribution and approval rules are reused. Calling sessions and saved information drafts use their existing state-only callers. The separate [recording contract](CALL-RECORDING.md) adds authenticated new-only binary audio storage and private playback; its actual deployed-storage proof remains pending. Unsupported provider analysis, sending, booking, discovery and general file actions return an explicit disabled response; they never report simulated external success.

## Configuration and access

With absent, partial or invalid configuration, `/desk/` and all its API routes fail closed before storage access. The protected preview requires the following **preview-scoped** environment fields; values do not belong in Git or build output:

- Netlify's trusted `context.deploy.context` must be `deploy-preview`; the function supplies it internally. No client or manually set environment value can enable production context.
- `EVZ_OPERATIONS_DESK_ENABLED=fictional-preview`.
- `EVZ_OPERATIONS_ORIGIN`, the exact HTTPS preview origin without a trailing slash.
- `EVZ_OPERATIONS_BLOB_NAMESPACE`, a new name beginning `evz-redesign-proof-` with 8–44 lowercase letters/digits/hyphens after that prefix. Never use a production store.
- `EVZ_OPERATIONS_OWNER_KEY`, `EVZ_OPERATIONS_FRIEND_KEY` and `EVZ_OPERATIONS_SESSION_SECRET`: three different independently generated 32-byte base64url values. Test fixtures contain public fake values and must never be used as deployed secrets.

Netlify supplies its scoped Blobs connection to the serverless function. This proof does not require copying a personal Netlify token or local CLI login. The owner configured these fields for Deploy Previews only. A real HTTPS proof at `0276568` read and wrote the same fictional Blobs record as both owner and friend, using sequential logins in one browser. It does not establish independent-device access. The existing preview's Netlify team gate remains in place. Application operator sessions do not bypass that gate or establish the friend's access from another computer without a separate supported hosting decision.

Observed Personal-plan UI limitation: selecting individual variable scopes requires an upgrade. Its secret import selects Builds, Functions and Runtime together, excluding post-processing. Functions-only scope is therefore not available on this plan. The owner approved that wider execution scope for Deploy Previews only. All other deployment contexts have empty values. No upgrade, production scope, branch/agent preview scope, local scope or permission change is authorized. The public `fictional-preview` enable flag was also classified as secret during import; its immutable classification caused a build false positive. Only that nonsecret key is omitted from scanning in Deploy Previews. Authentication keys remain scanned and masked.

Operator cookies are signed, HttpOnly, Secure, SameSite=Strict and expire after 8 hours. A signed same-origin CSRF cookie/header protects writes and login. Origin and fetch-site checks reject foreign origins. Responses and static shell contain no stored project payload; authenticated state is `no-store`. Keys are never returned in JSON. Rotate the session secret to invalidate both active sessions. Preview assets stay separate from the public site's `/studio/` paths.

A first-visit document navigation may load the empty public shell from another site. That exception does not permit cross-site API reads, writes or embedded private previews.

## Transaction boundary

`ConditionalLifecycleStore` implements the existing `snapshot/config/change` boundary with strong `getWithMetadata` and `setJSON(...,{onlyIfMatch:etag})`. Initial creation uses `onlyIfNew`. A stale writer fails rather than rerunning its callback. External effects must remain outside callbacks; the proof starts none. Every event has a caller-owned stable ID/fingerprint. If a mutation response is lost, a strong read reconciles that exact saved event. Otherwise the outcome stays uncertain; retain the same ID, read `/desk/api/events/<id>`, and replay the same event rather than creating another action. Concurrent retries converge on one saved event and one local email action.

The proof caps its complete envelope at 2 MB and refuses non-fictional or execution-enabled state. General adapter validation retains the existing 20 MB ceiling. A read-only size check found the installed operational state file is 13,415,305 bytes (11.34 MB compact JSON); it has not been uploaded. The preview projects event metadata and email status rather than retained provider receipts/full event payloads, and omits captured web-page bodies and reviewed-context bodies from routine dashboard reads. Source URLs, hashes, capture dates, exact claim excerpts, call transcripts and private notes remain. The current-record estimate falls from 5.41 MB to 2.98 MB before computed views; this is not a hosted capacity measurement. The preview still contains only one fictional project. Production migration still needs response-size, latency, conflict and credit measurement with an inert authorized copy; the fictional proof does not establish capacity for the real record set.

### Function UI packaging

The Netlify build runs `node scripts/build-desk-assets.mjs` before the public site build. It converts only the existing UI asset allowlist into the ignored `pipeline/hosted-assets.mjs`; the function imports that module so the bundler carries exact bytes without depending on a Lambda directory layout. Private state and environment configuration are never read by this build step. Missing internal UI files return a generic 503. Verify with `node --test scripts/build-desk-assets.test.mjs` and an actual preview request; a local test does not establish a successful remote deployment.

The pure `lifecycle-assets.mjs` manifest is shared by the local server, hosted handler and build. The hosted handler never imports the local HTTP server or starts its research-service dependency; that service computes a filesystem-based version only for the installed local host.

The hosted [notification preparation routes](TEAM-NOTIFICATIONS.md) are authenticated and have no external delivery effects. Their manual clock check is not a deployed schedule; local Codex/Gmail authentication is not part of the Netlify bundle.

### Exact retained source reads

Signed-in operators can open `/desk/retained-source/<project>/<sha256>?url=<encoded-url>&at=<encoded-capture-time>`. The local desk exposes the same route without `/desk`. The server searches only that project's retained captures, requires the exact URL, hash and capture time, verifies the existing text/context digest, and caps the response at 200 KB. It never fetches the URL or reads a caller-selected file. Missing, mismatched or corrupted evidence fails closed. JSON, `nosniff`, CSP and no-store headers keep untrusted captured content inert and private. Research distinguishes Saved capture from Live source; live pages can change.

The projection does not alter canonical state, compact history, migrate records or raise the fictional 2 MB envelope limit. A production migration needs an authorized inert copy, immutable backup/restore proof, measured response/write latency, conflicts and shared-plan credit consumption, plus an agreed retention boundary. Do not upload current client/prospect data merely to measure it.

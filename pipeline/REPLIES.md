## Read and retain

`reply.content` binds the Gmail message ID, Message-ID, In-Reply-To, thread, addresses, subject, source MIME SHA-256, retained-text SHA-256 and complete source hash. Plain UTF-8 content and base64url bodies are supported. Multipart alternatives prefer one plain text body. HTML is projected to inert text; scripts, styles and block quotes are excluded. Its original MIME hash remains retained, and the UI labels the projection. Attachment bytes are never fetched or copied. Different Reply-To, extra recipients, ambiguous/missing parts, unreadable encoding, partial/attachment-backed text and oversized sources hold preparation. A body hold still pauses cold contact; it cannot fabricate readable content.

Only the current verified reply can supply a draft. A changed body, MIME source, routing or thread creates a new source version and invalidates reply-dependent review/preparation. Prior source/draft/approval history remains retained. Delayed older replies cannot replace a newer current reply. Exact effect retries stay idempotent; no old message is edited.

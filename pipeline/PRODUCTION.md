# Production preparation and local operation

Studio Operations stores working records and owner decisions. SOSA discovers/stages prospects; the subscription controller authors and independently reviews detailed assessments. Apollo holds the owner's call tasks and executes email. Gmail verifies sent threads/replies, Calendar owns bookings, and the scoped Google identity projects status to the tracker.

The deterministic local service calls connected tools directly through the installed Codex 0.148.0 app-server. It starts an ephemeral connection session and no model turn. It reuses the existing ChatGPT sign-in and connected accounts; it does not extract cookies, accept new permissions, answer provider approvals, or use a paid model API. This chat is for setup and decisions, not the dispatch loop. SOSA/Dots is not the database or connector transport.

This follows the inspected installed schema and [official app-server protocol](https://learn.chatgpt.com/docs/app-server). Treat CLI/app updates as deliberate compatibility changes. Requested approval, changed account, missing tool or unknown result holds work. Research workers retain separate restricted environments without these connected tools.

## Native automatic email route to review

| 1 | EVZ Food Beverage - Email 1 ready | EVZ Email 1 subject | EVZ Email 1 body |

Select actual custom variables from Apollo's menu; do not guess tokens. Each sequence has one automatic email, zero delay, one subject/body variant and the verified business sender. ## Start, health, pause and recovery

Use Node 24 and the locked dependencies. Keep private state outside Git, restricted to owner/SYSTEM/administrators. Raw receipts, contacts and Google key references stay there. Initialization disables execution:

    $env:STUDIO_LIFECYCLE_STATE_DIR='C:\private\studio-operations'
    node lifecycle-cli.mjs init-production
    node lifecycle-cli.mjs status
    node lifecycle-cli.mjs service

The service binds the console to loopback, supervises bounded connector ticks and stores health privately. It starts no research/transcript model by itself. runtime.enabled controls polling; operations.enabled controls connector work; outreach_enabled and connector_writes_enabled require final release. Keep both earlier chat test heartbeats paused. Routine polling does not post here.

Install the owner's non-admin Windows startup task from the reviewed runtime:

    .\studio-service.ps1 -Action Install -StateDirectory 'C:\private\studio-operations'
    .\studio-service.ps1 -Action Start -StateDirectory 'C:\private\studio-operations'
    .\studio-service.ps1 -Action Status -StateDirectory 'C:\private\studio-operations'

It uses a hidden window, starts at owner logon, ignores overlaps and bounds restarts to three with one-minute intervals. Stop validates the exact installed runtime, private lock, process command and creation time, then closes the owned Node tree as well as the scheduler wrapper. Changed/unknown identities hold instead of killing another process. Dead locks and reservations remain for exclusive recovery on restart. The computer must be on/awake, the owner session available and existing connector authentication usable. No active chat is needed. Reboot/logon, sleep recovery and disconnected-account behavior require separate measurement from a running-host proof.

An exclusive Windows named pipe serializes startup. Only its owner can archive locks with a confirmed dead process. Live/unknown locks hold. Saved receipts settle before new work; uncertain mutations follow authoritative readback and never replay. Failure does not erase stops/approvals/reservations. The console reports runtime state, last check, holds, projection and backup.

**Pause all** or the CLI pause command disables connector work, outreach and inference while preserving reservations. When the production research directory is bound, the same action also disables and reads back its research-control file; the console reads research permission/priority from that same source. An unavailable control leaves an explicit exception and never reports that research stopped. To stop the host, use the startup script's Stop action and verify its owned process exited. Keep recovery archives/receipts. Restored backups disable execution and need rebinding/review. Never clear a hold just to make the screen green.

## Final release, upkeep and verification

Every gate needs evidence: design, business sender/address, native route, controlled send/stops, site/inquiry, reviewed supply and capacity. Final approval binds sender, native route, calendar, campaign, projection and evidence fingerprint:

    node lifecycle-cli.mjs status
    node lifecycle-cli.mjs release CURRENT_REVIEW_FINGERPRINT OWNER_APPROVAL_REFERENCE

Use this only for actual recorded owner approval after review; incomplete gates fail. It enables neither research nor native sequences/workflows. Native activation and controlled rehearsal remain separate explicit steps.

Review exceptions/callbacks daily. Weekly, verify mailbox health/allowance, reconcile due work, inspect sampled evidence/outcomes and check backups. Upkeep target remains 1–2 hours/week, not a guarantee. Active records/projection are bounded to 500, with event/state size limits; archive/reconcile completed campaigns before those limits while retaining restrictions. No automatic deletion policy is introduced.

Run npm run check and npm test. Coverage includes source-review import/tampering/deduplication, release fingerprint, native intent recovery, suppression, callbacks, guest checks, connector approvals, reservations, locks and restore. Connected proof verifies exact accounts/scope, retains raw receipts privately, checks independent readback, confirms no extra send/intent and stops bounded test schedules.

Live contact remains off until account and proof gates pass.

## Recovery, upkeep and launch

Backups checksum operating state and restore only into a new directory. The [complete local package](#complete-local-backup-package) includes declared original/authoring dependencies and stored audio. It excludes configuration/credentials, worker prompts/logs and external provider receipts; retain the separate private provider receipt archive. Restore disables AI, connector writes, research and outreach, and makes Pending mutations Uncertain. Explicitly rebind providers; a restored copy must not become another executor.

### Complete local backup package

Partial manual original declarations and Drive Reading/Ready/Held receipts are required dependencies, including a declaration with zero uploaded chunks. [Explicit original recovery](GOOGLE-DRIVE-ORIGINALS.md#explicit-incomplete-original-recovery) closes exact publication authority and preserves bounded observed chunks as hash-named inert bins, with absent/corrupt/unavailable and unobserved-range dispositions. G1 validates these before export/restore; the exact [shared operations originals](SHARED-OPERATIONS-ORIGINALS.md) import path preserves validated inert bins; unsupported earlier shared importers reject before writes. A healthy completed original still requires actual whole-file and recorded-chunk verification. A recovery package preserves observations and uncertainty, never a usable partial PDF or proof that an in-flight writer stopped.

The separately disabled [fictional hosted authoring reader](PROJECT-AUTHORING.md#disabled-hosted-authoring-storage-and-caller) downloads the same validated schema-2 package and dependencies through signed bounded reads. It holds missing/corrupt required dependencies and unfinished attempts until [explicit incomplete-attempt reconciliation](PROJECT-AUTHORING.md#explicit-incomplete-attempt-recovery) retains exact available evidence and missing/uncertain dispositions. A complete package of known incomplete work does not make a partial export usable or attest that a renderer stopped. This source integration does not establish an automatic cloud backup, D2 export permission, real remote storage or computer-off recovery.

The existing `backup`/`restore` commands above and daily maintenance use one version-2 package: `<backup-file>.json` contains checksummed state and an exact path/size/SHA-256 manifest; `<backup-file>.json.files/` holds content-addressed file bytes. **Copy and retain both together** in owner-controlled private storage. Identical content is stored once. This is a bounded local package, with no automatic cloud copy, encryption service, account/credential recovery, hosted originals or computer-off execution.

The inventory follows existing records, including retained work/attempt history. It includes all `verified_original` PDFs; authoring context, submitted input and editable `authored.json`; immutable runtime declarations; complete export receipts, reviewed PDF/page renders; declared project-owned original raster images; and verified stored audio. Asset provenance, approvals, source/resource/export hashes, scope/price and held companion drafts stay in state. Each held attachment and authoring reference must match an archived version. Reference-only files remain explicitly reference-only. An in-progress export without a complete receipt is not promoted into a reviewed artifact; its saved source/claim remains available for inspection and explicit recovery.

Unknown directories, arbitrary private-path references, local configuration/credentials and executable scripts/tools are not copied. The explicit Node PDF route retains registered hash-verified font/image/template bytes in portable runtime evidence and canonical page JSON plus actual reviewed PNGs; its renderer source/lock fingerprints remain disabled evidence. The local Python route still requires separately trusted installed tools/fonts. Original image bytes are saved under `project-authored/JOB/image-ID.EXT`, with exact hashes; no old resource path is followed during restore. Original renderer code is checked at backup and represented only by `renderer-evidence.json`. `runtime.json` retains the immutable historical declaration and original digest as evidence, without supplying executable code or a runtime configuration. Complete receipts can resume read-only verification; new rendering always needs an explicit newly trusted runtime argument and resource/path bindings. For the local Python route, recover installed proposal resources/fonts separately and bind restored image paths deliberately.

Package bounds: 25 MB JSON envelope, at most 6,000 dependency paths and 512 MB total declared bytes; 64 MB per PDF/original image, 4 MB per source/context/canonical JSON (36 MB for bounded portable Node runtime evidence), 16 MB per rendered page and at most 16 pages per export. Existing audio bounds remain 4 MB/clip, 2,000 clips and 200 MB total. Source/manifest paths, directory ancestors, regular-file type, lengths, hashes and dependency completeness are validated. Missing/corrupt/oversized dependencies, traversal, symlinks/junctions, duplicate or undeclared entries fail before a usable destination exists. A legacy version-1 backup remains readable for state/audio without project dependencies; a legacy bundle claiming verified originals or authored source is rejected as incomplete. Regenerate it from the intact source workspace rather than clearing verification claims.

Backup holds the existing source lock, checks bounded dependency bytes, flushes writes and publishes its final JSON exclusively after all blobs exist. Restore validates the whole package before exclusively creating a destination; it writes disabled configuration and publishes state last. Existing destinations/output paths are never replaced. Caught failures remove only the directory created by that attempt, after checking its identity; a completed published restore is retained even if final temporary-file cleanup fails. An abrupt process stop can retain an incomplete `.files/` directory or destination without published state. Retry with a new name. After verifying the exact stopped process and resolved private paths, an authorized operator may remove only that operation's orphan; never remove unrelated paths or a live/unknown source lock. These checks cover process interruption, not hardware/media survival.

# Call desk release

The October 18 interview selected the existing local host, a list and call card, two explicit queues, manual phone calls, optional owner notes, booking first and an information email alternative. No additional subscription is installed. This release implements those interactions while retaining the separate production contact gates.

## Operation

Today shows due, fresh, unrestricted unique businesses. Due callbacks precede pitch-ready records and verification calls. The two-day target is 100 eligible businesses; a dashboard notice appears below 50. Future callbacks, expired checks, stopped businesses and exhausted campaigns do not inflate available supply. Research idles at a full buffer, preserves website/client priority and the 30% reserve, and continues only the already approved finite campaign. Two new jobs with the same technical failure stop further research under that source version; old holds are retained, not retried. A reviewed code correction starts a new failure-observation baseline without resetting job attempts or provider reservations.

Save a completed call with one of the outcome buttons. Callback requires an exact future time. Interested offers discovery or information. Notes are optional; browser dictation or Windows + H enters the owner's own summary. Nothing records the telephone conversation. Review dictated text before saving. Verification conversations require explicit identity, activity, decision-maker and goal confirmation before advancing. This owner attestation does not rewrite the original independent research grade.

Undo reverses only the latest quick-call event before another decision, draft, booking or provider action. The original event remains in history. Contact restrictions cannot be undone into outreach. Notes can be corrected with a new audit event. Saved calls and follow-ups remain accessible from Today. End calling session stores attempts, conversations, interest and bookings, without pausing research.

Discovery uses live calendar availability, 20-minute slots within weekdays 9–5 Eastern, and 15-minute buffers. Video is the default; phone is selectable. Confirm guest name, email and time before queuing. The existing connector controller rechecks availability before creation and verifies the exact event, including a video link when requested. A reserved invitation is never blindly recreated. An existing meeting requires reconciliation/rescheduling rather than a second invitation.

The information message is an editable local draft derived from the selected idea and owner notes. Saving does not send it. Approve and send binds the exact saved recipient, subject and body, with an explicit recipient confirmation. Gmail uses the verified business account through the existing deterministic connector transport. A durable reservation precedes dispatch; an uncertain receipt holds the message for Sent-folder reconciliation and cannot authorize another send. “Sent” means the provider acknowledged a message identity, not inbox placement. Fictional mode simulates both invitations and sending without any connector call. The revised release fingerprint invalidates earlier contact approvals for the old workflow.

## Source tools and limits

Retained assessments, source packets, independent reviews and attempt history are reused. The citation correction copies complete context anchors and forwards only a fixed validator diagnostic to bounded recovery. It does not weaken evidence validation or replay exhausted jobs.

SOSA's public business/social browsing, state registries, vendor directories and chamber listings can supply retained source evidence. They are not all unattended controller adapters. Hunter, Wappalyzer, Screaming Frog, ICANN/MX checks and monitoring tools were discussed as candidates; this release neither installs them nor spends enrichment credits. HTTP capture handles approved public pages; authenticated/social browser inspection still needs staged reviewed captures. Technical audit tools do not establish business ownership or buying interest.

The host must remain awake with its owner session and existing authentication available. No active chat is needed for the saved campaign. Automatic discovery beyond the named scope, 50/day sustained replenishment, sleep/reboot recovery, business-mailbox cutover and real video-link delivery remain acceptance work until measured. The dashboard must not label 151 staged records as 151 detailed research acceptances: the observed existing supply was 18 research-reviewed and 133 verification cards, with no new calls or research performed during implementation.

## Verification and release

Focused coverage includes complete context anchors and bounded recovery, call idempotence/undo/restart, callbacks/stops, exact message approval/lost receipts, fictional booking, Eastern DST/hours/buffers, and repeated technical failures. Supplemental sidecar and Windows task identity code were reconciled from the installed runtime; the superseded raw model-error feedback patch was not retained.

Browser rehearsal uses a separate private directory and loopback port. Initialize controlled `StudioLifecycle`, import `fixtureProspect` records, then call `serveLifecycle(app,{port:8819})`. Never use production contacts for this test. Confirm the controlled banner, execute no-answer/undo/interested/booking/draft/send simulation/end-session, and independently inspect persisted records. Test verification confirmation and callback/stop paths. Stop only the fixture process afterward. No rehearsal data belongs in Git.

Observed checks: 260 account-free tests and syntax passed; browser outcomes and persisted records matched at desktop and in a 390px fixture frame, and desktop had no document overflow or console errors. Screenshot capture repeatedly timed out, so screenshot-based visual review is inconclusive. Browser dictation microphone permissions and connected real sending/video booking were not exercised.

Deploy tracked files and locked dependencies into a new versioned private runtime. Keep the original configuration, source captures and reservations outside the checkout. Stop the old service with its own reviewed script; preserve a complete private pre-release operations snapshot, original task XML/action and prior runtime. Repoint the existing scheduled task to the new script, start it and compare `/api/state`'s `build.source_sha256` with `runtimeVersion()` from the release. That startup fingerprint stays fixed for the process, exposing source changes that have not been reloaded. Confirm record/event/reservation counts and disabled contact controls before accepting the deployment.

Rollback: stop the new service using its script, restore the old task action and start the retained prior runtime. Do not restore stale state over later calls, contact restrictions or provider receipts. Additive call-desk fields can remain in private state, but the old UI cannot manage them. Any external effect must be reconciled at its provider; rollback never authorizes replay.

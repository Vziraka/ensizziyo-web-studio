# Disabled shared operations records

`shared-operations-records-v1` combines [manual records](SHARED-MANUAL-DISPATCH.md), signed [project feedback and protected requests](SHARED-PROJECT-CONTINUATION.md) and the existing internal dispatcher in one `dispatchBinding`, namespace and `workspace` CAS authority. It saves supported human requests; it does not start authoring. Existing internal-only, manual, project, refinement, research and inert profiles retain their separate boundaries.

The [exact proposed policy](shared-operations-records.example.json) is UNAPPROVED. Real recipients, role verification, grant, deployment, dates and measured finite allowances remain blank. All runtime/build flags remain unset by default. A fresh prepared manifest has kind `shared-operations-records-source-v1`; its policy and manifest bind this exact `human_events` partition:

```json
{"version":1,"manual":["note_added","call_logged","call_claimed","follow_up_handed_off","contact_stopped"],"project":["asset_feedback_added","asset_version_selected","asset_version_disputed","project_preparation_requested","concept_refinement_requested","unpaid_refinement_exception"]}
```

Notes use only `manualRecord`. Each write selects exactly one `dispatchTransition`, `manualRecord` or `projectRecord`; unknown/multiple/cross-profile options reject. The same existing manual/project reducer is independently replayed over the entire prior state. Config and manifest are immutable. Human receipt ID, event/actor fingerprint and config fingerprint must match the typed request. Mutation time is captured inside the CAS callback after its awaited state read. A nonduplicate human event prepares current held attention in that same transaction with `includeDigest:false`; exact retries do not change revision or prepare more messages.

Both signed roles retain equal design authority and full project/history visibility. An uncontested selection can approve a baseline immediately; an explicit dispute retains that baseline until fresh matching choices resolve it. Always/Never feedback follows the existing automatic/project/studio scope rules. The current context retains original references, verified originals, approved baseline, feedback, conflicts, assignment and work history. The owner-only account/spend/recipient policy does not govern design approval.

A manually recorded interested call saves its attestation without creating authoring work. An explicit eligible `project_preparation_requested` can queue existing website work. A focused refinement uses the exact prepared version, selected direction and feedback, with one included unpaid round and explicitly approved single-round exceptions. In this profile a new request against a version different from that asset's approved baseline rejects before changing any state or consuming a round/exception. Select/reagree first. A request against the current approved version may retain an open dispute; existing authoring rules preserve the approved baseline/conflicting properties. Exact previously saved requests remain valid receipts after later selection changes. Any future execution must reload current context; a saved request conveys no retry or authoring permission.

Manual handoff moves eligible Ready work assignment while preserving its current execution and historical evidence. Stop and subsequent incoming replies retain the restriction. Context, assignment, stop, selection and dispute changes fence the existing authoring reducer against stale output; no source, current claimed/rendered evidence or history is overwritten. Incomplete authoring still blocks complete G1 until its existing explicit recovery is performed elsewhere. This composition does not add recovery/authoring write authority.

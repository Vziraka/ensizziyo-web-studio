## Subagent routing pilot

November 1, 2026: the owner approved evaluating and implementing task-appropriate subagent choices after the earlier pilot inherited Terra Max for narrow tasks. Start with this repository; other EVZ projects and clients are not yet verified. Select a model and reasoning level for the delegated task when the host supports an explicit choice, rather than assuming a fresh conversation changes either. An explicit owner choice takes precedence. Do not spawn an agent for a task the lead can handle more simply.

- For a bounded, low-risk evidence extraction or lookup, consider Luna High and have the lead check material results against the cited source. The optional project role is [`evz_evidence`](../.codex/agents/evz_evidence.toml). It does not authorize release, security, access or delivery decisions.
- For a small, ordinary code review, consider Sol Medium as an advisory reviewer; the optional project role is [`evz_routine_review`](../.codex/agents/evz_routine_review.toml). The lead checks the result and escalates uncertainty or wider risk. It is not a substitute for the required independent consequential-work reviews.
- For substantial operations changes, broad audits, security-sensitive work, or unclear/high-impact findings, retain appropriately capable independent reviewers and use more reasoning where warranted. Neither narrow profile replaces the distinct requirements and engineering reviews in [WORKFLOW.md](../WORKFLOW.md#review-and-pr-evidence). Consider different capable models or efforts when a second perspective is useful; no specific expensive model or Astra High swarm is a default. If capable independent review is unavailable, report the missing gate.

Escalate a narrow task when evidence is incomplete, results conflict, the impact is higher than expected, or the agent misses requirements. Record the model and effort actually used, the reason and relevant observed usage when available; say unknown when the host does not expose them. The two TOML roles are optional, project-scoped configurations for clients that discover custom agents. Their pinned model and effort take precedence in those clients: when the owner requests different settings, do not invoke the conflicting role; use an allowed direct override or report that the host cannot apply it. The lead can choose equivalent explicit spawn settings where supported. These files do not create a sandbox, enforce routing, or change the parent model; a running chat is not guaranteed to reload them. If a suggested role or model is unavailable, retain the existing authorized route and report the limitation. Do not silently substitute for an exact owner-specified model, buy credits, switch providers or weaken review. Explicit settings and client behavior vary: see [OpenAI's subagent documentation](https://learn.chatgpt.com/docs/agent-configuration/subagents).
